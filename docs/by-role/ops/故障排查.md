# 故障排除指南

## 快速诊断

### 查看服务状态

```bash
./scripts/start_rangen.sh status
```

### 健康检查

```bash
curl http://localhost:8000/health
```

### 查看日志

```bash
tail -f logs/research_system.log
```

## 常见问题

### 问题：服务启动失败

**排查步骤**：
1. 检查端口是否被占用：`lsof -i :8000`
2. 检查依赖是否安装：`pip list | grep -E "fastapi|streamlit"`
3. 查看错误日志

**解决**：
```bash
# 停止现有服务
./scripts/start_rangen.sh stop

# 重新启动
./scripts/start_rangen.sh start
```

### 问题：端口被占用

**检查端口占用**：
```bash
lsof -i :8000
lsof -i :8500
```

**解决**：停止占用端口的进程，或使用其他端口

### 问题：API 请求超时

**原因**：
- 网络连接问题
- 服务未正常响应
- 查询过于复杂

**排查**：
```bash
curl http://localhost:8000/health
```

### 问题：前端页面打不开

**检查**：
1. Streamlit 服务是否运行：`./scripts/start_rangen.sh status`
2. 浏览器访问的端口是否正确

| 服务 | 默认端口 |
|------|----------|
| API | 8000 |
| 统一入口 | 8500 |
| 聊天 | 8501 |
| 管理平台 | 8502 |

### 问题：认证失败

**检查 API Key 配置**：
```bash
echo $RANGEN_API_KEY
```

**设置 API Key**：
```bash
export RANGEN_API_KEY=your_api_key_here
```

## 性能问题

### 内存占用过高

**检查内存使用**：
```bash
free -h
```

**可能原因**：
- 缓存数据过多
- 并发请求过多
- 内存泄漏

**解决**：重启服务清理缓存

### 响应速度慢

**检查**：
1. API 服务是否正常：`curl http://localhost:8000/health`
2. 网络延迟
3. 查询复杂度

## 日志分析

### 日志位置

```
logs/
├── research_system.log     # 研究系统日志
├── langgraph_workflow.log # 工作流日志
├── api_server.log         # API 服务日志
```

### 查看实时日志

```bash
tail -f logs/research_system.log
```

### 日志级别

通过环境变量设置：
```bash
export RANGEN_LOG_LEVEL=DEBUG
```

## 紧急恢复

### 完全重启

```bash
./scripts/start_rangen.sh stop
sleep 2
./scripts/start_rangen.sh start
```

### 清理并重启

```bash
# 停止所有服务
./scripts/start_rangen.sh stop

# 清理缓存
rm -rf logs/*.log
rm -rf src/data/*.db

# 重启
./scripts/start_rangen.sh start
```
