# 📊 RANGEN 评估系统使用手册

## 📖 关于本手册

本手册介绍RANGEN系统的**评估框架**和**使用方法**。评估系统用于全面评估AI中台的核心能力，帮助团队了解系统现状、发现短板、指导优化方向。

### 评估框架

| 评估模式 | 维度数 | 测试数 | 说明 |
|----------|--------|--------|------|
| **E2E集成测试** | 24个 | 79个 | 调用真实API验证系统能力 |
| **静态代码分析** | 2个 | - | 分析源码结构验证系统质量 |
| **统一评估** | 26个 | 79个 | E2E + 静态综合评估 |

## 📐 评估模式说明

### 📡 E2E集成测试（24个维度）

通过调用真实API验证系统能力：

| 类别 | 维度 | 说明 |
|------|------|------|
| **A.基础能力** | 编排能力、Agent完备性、Prompt工程、上下文工程 | 核心功能测试 |
| **B.智能能力** | 响应质量、路由机制、推理能力、知识召回、工具调用、多轮对话、自学习 | AI能力测试 |
| **C.架构能力** | Harness治理、可观测性、监控告警、故障自愈、灰度发布 | 架构功能测试 |
| **D.数据能力** | 数据源接入、知识管理、向量管理、数据血缘 | 数据处理测试 |
| **E.平台能力** | 应用支撑、成本控制、集成扩展 | 平台功能测试 |
| **S.安全能力** | 安全防护 | 安全能力测试 |

### 🔍 静态代码分析（2个维度）

通过分析源码结构验证系统质量：

| 维度 | 说明 |
|------|------|
| **架构合理性** | 模块结构、分层设计、依赖关系 |
| **代码质量** | 复杂度、文档覆盖、测试覆盖、命名规范 |

## ❓ 常见问题

### Q: 评估失败怎么办？

```bash
# 检查API服务是否运行
curl http://localhost:8000/health

# 检查评估日志
python -m evaluation.main --mode=static
```

### Q: 如何跳过某些评估？

修改 `evaluation/main.py` 中的 `E2E_DIMENSIONS` 或 `STATIC_DIMENSIONS` 列表。

### Q: 评估超时？

增加 `--max-concurrent` 参数减少并发，或减少 `--sample-count`。

## 🔧 扩展评估器

### 添加新评估维度

1. 在 `evaluation/e2e.py` 或 `evaluation/static.py` 中添加新维度
2. 更新 `main.py` 中的 `DIMENSION_META` 配置
3. 在 `v2_capability/test_data/e2e_tests.py` 中添加测试用例

### 评估器模板

```python
async def evaluate_dimension(dimension_id: str) -> Dict[str, Any]:
    """评估单个维度"""
    return {
        'dimension': dimension_id,
        'score': 0.85,
        'status': 'completed',
        'test_count': 5,
        'passed_count': 4,
        'failed_count': 1
    }
```
